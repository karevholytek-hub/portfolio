# Prompt Iteration Engine

**Когда читать:** создание дизайна, изображения, HTML, документа или другого результата, если пользователь требует автопроверку, многократные исправления, качество ≥ заданного порога или запуск «пока не пройдёт QA». Сначала прочитать этот навык, затем предметный.

## 1. Контракт, который нельзя потерять

До первой генерации зафиксировать: задачу, исходные файлы и версии, подтверждённые требования (MUST), художественные цели (SHOULD), неизвестное (UNKNOWN), запрещённые подмены (FORBIDDEN), целевые метрики, допустимые инструменты и пределы расхода. Не придумывать данные; параметры из документов важнее произвольных параметров на картинке.

Отдельно записывать происхождение чисел, доверие к ним и возможность автоматического измерения. Дизайн «95 из 100» не подтверждён надписью 95/100 на сгенерированном изображении.

## 2. ИТЕРАЦИОННЫЙ ПРОТОКОЛ

1. **Baseline**: сохранить неизменённое исходное ТЗ, v0 промпта, эталонные размеры, примеры плохих решений и явные жёсткие гейты.
2. **Generate**: создавать один предмет/концепцию за одну генерацию, чтобы композиционные ошибки не маскировались коллажом. Фиксировать номер версии, исходник, файл, модель/режим при наличии и SHA-256.
3. **Measure**: проверять программно только действительно измеримые параметры (разрешение, число объектов, пиксельные отношения, формат, наличие текста). Пиксели не доказывают миллиметры, текст генератора не доказывает свойства материала.
4. **Expert QA**: отдельно оценивать гармонию, реализм, конструкцию, уникальность, качество исполнения. Статусы PASS/FAIL/UNKNOWN с доказательством и уровнями BLOCKER/MAJOR/MINOR.
5. **Root cause**: присваивать код GEOMETRY, LAYOUT, STYLE, PHYSICS, FACT_HALLUCINATION, OUTPUT_FORMAT, NOVELTY, TOOL_FAILURE; выяснять, ошибка в промпте, самой модели, данных или неверном замере.
6. **Revise**: при каждом FAIL создавать новый промпт с проверяемой правкой: *было → причина → изменение → ожидаемый признак успеха*. Не накапливать противоречащие запреты. За основу брать исходные MUST, а не последнюю случайную генерацию.
7. **Rerun**: повторить генерацию и все затронутые тесты. Если выполнялась локальная деформация изображения, повторно проверять соседние контуры, детали, отражения, крепления.
8. **Stop**: не запускать бесконечно. Максимум попыток/бюджет, неизменный выходной SHA, повторяющиеся ошибки, недоступность инструмента, требуется независимый эксперт → LIMIT/NEEDS_REVIEW/BLOCKED с прозрачным отчётом.

**Правило изменения метода:** после 2 повторов той же ошибки переходить от словесного промпта к жёсткому шаблону, маске, размерной SVG/CAD-основе, ручной компоновке или иному проверяемому способу. Не писать десять раз «не делай широким», если генератор игнорирует запрет.

## 3. QA не подменяется саморекламой модели

Зелёная галочка, сертификат, число «95/100» и размеры, нарисованные генератором, — элементы пикселей, **не** доказательства. Сначала независимая программная промерка, затем художественное/техническое заключение; физическую надёжность и безопасность проверяет компетентный человек. Отдельно соблюдать требование клиента «без ИИ» для конечной сдачи; не маскировать происхождение.

## 4. Машинный журнал

В каждом запуске хранить prompt_vNN.md, candidate_vNN, qa_vNN.json, хэш, массив fail-кодов, предложенное исправление, статус, отличия от предыдущего. Сохранять короткие универсальные уроки с источником/датой и статусом hypothesis|tested|accepted. Не выкладывать клиентские исходники, фото, коммерческие задания и переписки в общую базу без разрешения.

## 5. Запуск

Локальный runner: skills/prompt-iteration-engine/run_loop.py, пример параметров: example_config.json. Он принимает уже настроенные внешние CLI генератора и QA, не вызывает сам облачную модель и не создаёт фоновые задачи без запуска; результаты проверок передаются через JSON. Параметр requires_human_review=true по умолчанию: машинный геометрический PASS заканчивается NEEDS_REVIEW, а не вымышленной экспертной оценкой. MAX_ATTEMPTS ограничен.

При генерации прямо в ChatGPT без внешнего CLI используйте те же шаги последовательно в текущем задании. Не обещайте работу после завершения ответа без реально созданного расписания.
