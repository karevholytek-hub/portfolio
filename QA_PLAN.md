## Правило каждой итерации

1. Зафиксировать одну правку и то, что она должна улучшить.
2. Провести автоматические тесты и снять реальные кадры страницы.
3. Оценить движение на скорости 1× и сравнить с фотографиями Мышки, без оправдания дефектов кодом.
4. Отметить FAIL, PASS или UNVERIFIED по всем затронутым воротам. Не использовать PASS без сохранённого доказательства с SHA-256.
5. При FAIL не публиковать: исправить и перепроверить.
6. После 8 × PASS проверить реальную сборку, сверить SHA-256, только затем предлагать обновление публичного сайта.

Для более точной анимации могут помочь дополнительные видео Мышки с подниманием лапы и умыванием, но текущая работа по QA не зависит от них. Не выдавать техническую демонстрацию за окончательный результат.

## Публикация и защита

CI на push/PR проверяет техническую часть и сохраняет скриншоты. **Зелёный CI не равен допуску к публикации**: отдельно запускается python qa/check_release.py --mode release. Для принудительного блокирования прямых push в main GitHub требует настроить branch protection с обязательными проверками: сам workflow такого права не создаёт.
